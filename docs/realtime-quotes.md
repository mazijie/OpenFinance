# 行情流处理学习链路

这条链路使用腾讯行情快照，不能还原逐笔成交。窗口数值是每分钟采样的价格统计，不是 K 线。采集时间不是交易所报价时间；腾讯返回的行情时间单独保存。该第三方接口的长期频率、稳定性与盘中时效尚未验证。

实时行情和 Airflow 已包含在默认 Compose 服务中。使用已有的 `.env`，以下命令在项目根目录执行：

```bash
bash scripts/compose.sh up -d --build
docker compose logs -f quote-collector quote-consumer flink-submit
```

首次启动会运行后端数据库迁移。实时模式通过后端刷新腾讯证券名单并保存到 PostgreSQL；刷新失败时使用最近的非空腾讯缓存并记录缓存日期，没有可用缓存则报告失败。采集以每批最多 500 只并发请求；北京时间交易日交易时段按整分钟启动，前一轮未完成时下一轮仍会启动。每轮独立记录采集状态，慢轮次可能晚于后续轮次写入 Kafka。持续阻塞的轮次会累积并增加并发请求数。日历未知时不访问上游，批次失败按 2、4、8 秒重试。支持沪深京代码映射，北交所仅对一只证券完成非交易时段单次请求验证。交易日历由后端 `/internal/jobs/trading-day` 提供，需设置与后端一致的 `OPENFINANCE_INTERNAL_API_TOKEN`。页面每 15 秒刷新；后端 `QUOTE_STALE_SECONDS` 默认 300 秒。无法保证第三方接口不会限流；如持续超时或拒绝，应停止采集器。

修改 Compose 中的 `CALENDAR_URL` 后，需要重新创建采集器容器才能更新环境变量；单纯 `restart` 不会应用新地址。使用与部署时相同的 Compose `-f` 参数执行 `docker compose up -d --no-deps quote-collector`。如果日志出现旧地址 `/internal/jobs/investment-monitor/trading-day` 的 404，说明运行中的容器仍保留旧配置。修复后，采集器在下一个交易时段的整分钟继续采集，不会自动补回漏采的盘中记录。

Airflow 任务 `openfinance_trading_calendar_sync` 每天北京时间 06:00 使用 BaoStock 的 `query_trade_dates` 查询当天及之后 30 天；每次执行一次查询，手动运行和当天定时运行相互独立。任务校验返回日期连续且包含今天和明天，再保存 Bronze 响应、更新 Silver 日历并回读检查。失败不会将缺失日期当成休市，定时任务不自动重试；可检查 Airflow 日志后手动重跑：

```bash
docker exec openfinance-backend python -m backend.ingestion.jobs.sync_trading_calendar
```

该接口提供的是上交所日历，当前仅写入 `SH` 标识；系统级开市判断使用现有日历读取逻辑，不能视为已经独立核验深交所及北交所日历。证券范围仍取最新可用缓存，缓存日期不一定是当天；第三方日历或报价服务的可用性不能保证。

非交易时段或数据源不可用时设置 `QUOTE_MODE=mock`，模拟数据每分钟产生一次，默认包含 600519.SH、000001.SZ，可通过 `QUOTE_SYMBOLS` 设置。页面会显示 `mock` 来源。不要把模拟数据视为市场验证。

```bash
docker compose exec kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server kafka:9092 --topic quotes.raw --from-beginning --max-messages 2
```

服务地址为 `http://localhost:8083`（Flink）和 `http://localhost:8000/api/realtime-quotes?symbol=600519.SH`。页面与问答使用同一个 PostgreSQL 查询服务；问答的截止时间早于现有快照时返回没有更新。股票涨跌分布按采集轮次计算，未完成时页面提示部分行情暂未纳入。上证指数、深证成指和创业板指独立采集并存储，不参与股票统计；接口的 `indices` 返回最近快照及其状态。部署需升级数据库迁移并重新构建行情采集器。

一分钟窗口按 `captured_at` 的 UTC 采集时间计算，只包含 `valid` 快照，最高、最低及平均值是**采样统计**。Flink 通过水位线允许乱序，`QUOTE_LATENESS_SECONDS` 默认为 120，可设置 0—1800 秒；修改后需重新提交 Flink 作业。水位线由每个 Kafka 分区上的定时心跳推进，采集器不访问上游也会继续发心跳，因此休市空闲时可关闭最后的窗口。采集器、Kafka 或 Flink 不可用时心跳不能保证推进，窗口可能延迟关闭。每条心跳会占用 Kafka 消息空间；采集时间必须为 UTC，Flink 的时间提取精确到秒。

当数据的采集时间不晚于当前水位线，在线统计不会纳入该快照；Flink 将其写入 `quotes.late`，消费者幂等记录到 `openfinance.realtime_quote_late`。页面在存在未处理的超期窗口时提示，API 返回 `late_windows`。超期判断按水位线保守执行：即使该分钟窗口还未最终关闭，只要事件已经落后于水位线，仍记录并交由重算处理。行情事件以轮次和股票生成稳定 ID，Flink 去重和市场聚合状态保留至少 25 小时；采集时间超过 24 小时的原始事件不再参与在线处理。

### 查看和重算窗口

先查看 API 的 `late_windows`，或查询数据库 `openfinance.realtime_quote_late` 中 `resolved_at IS NULL` 的记录。在 Kafka 原始消息仍可覆盖目标区间时，指定**包含开始、不包含结束**的整分钟时间范围运行：

```bash
docker compose run --rm --no-deps quote-consumer python -m realtime.recompute --start 2026-11-01T09:30:00+08:00 --end 2026-11-01T10:00:00+08:00
```

重算读取 `quotes.raw` 各分区从当前最早位置到启动时捕获的结束位置，按股票与轮次取首条、按采集时间计算，并在数据库事务中写入结果、处理已覆盖的超期记录及登记 Kafka 位置。它不会调用腾讯或修改消费者组位置。在线结果和重算共用数据库锁；重算结果不会被后到的旧结果覆盖，若之后收到不同的在线结果会标为待复核，需在数据到齐后再次重算。Kafka 快照之外的新消息不在这次重算中。

若某分区已有消息被清除，程序检查最早保留消息的 Kafka 时间是否早于所请求的开始时间；无法确认时拒绝写入。这依赖生产者的 Kafka 消息时间与实际发送时间一致、机器时钟正常，不能证明上游或 Kafka 之前的数据完整。为避免误删数据，重算只更新实际读到有效样本的窗口，不删除目标范围内其他窗口；分区数变化后如果同一股票轮次跨分区出现，将拒绝重算。大量数据需扫描保留期内消息并在内存中保存去重键，应选择空闲时段并监控资源。

上线时先停止旧版采集器、Flink 作业及结果消费者，执行数据库迁移 0008，再启动新版组件；不要让新旧作业同时处理同一链路。已有处理时间窗口保留但标为 `legacy_processing_time`，不会冒充采集时间窗口；旧版 Kafka 结果重放也不能覆盖新版窗口。新拓扑与旧 checkpoint 不兼容，应按运行环境重新提交并核对作业数量；原始 Kafka 保留期内的数据可供重新处理或按上述方式重算。不要清空现有业务数据。

### 恢复和恰好一次边界

采集结果、个股指标及 outbox 记录在 PostgreSQL 同一事务中提交。`quote-outbox` 逐条发布未完成记录，Kafka 确认后标记完成；确认后崩溃可能导致重发，Flink 在聚合前按事件 ID 去重。四个行情输出和过期事件输出使用 checkpoint 和 Kafka 事务，消费者只读已提交消息，并在同一数据库事务中保存 inbox 标记和业务结果。Kafka offset 随后提交，重放已处理消息不会重复写库。指数采集仍独立进行。

有效期从 `captured_at` 起算 24 小时，超过有效期仍在 outbox 的事件会标记 `expired` 并记录日志；已经进入 Kafka 但超过有效期的事件由 Flink 过滤，并按事件 ID 记录在 `realtime_quote_expired`。可用以下查询查看发布积压和过期数量：

```sql
SELECT state, count(*), min(captured_at) FROM openfinance.realtime_quote_outbox GROUP BY state;
SELECT count(*) FROM openfinance.realtime_quote_expired;
```

Kafka 默认保留 72 小时（`REALTIME_KAFKA_RETENTION_HOURS` 不应设置为小于 72）。outbox 和 inbox 当前不自动清理；监控数据库空间。不要删除 inbox 后重置消费者 offset，也不要在保留 inbox 的情况下删除并重建同名 topic，否则 offset 身份可能冲突。保证依赖 Kafka、PostgreSQL 和 checkpoint 数据保持可用，以及机器时钟同步；单 broker 和本地 checkpoint 不提供高可用。不能保证上游未返回、持久化前丢失或已过期的行情完整。

升级到迁移 `0021_realtime_outbox_inbox` 时，先停止旧采集器，等待旧 Flink 和消费者排空现有消息，再停止旧 Flink 作业及消费者。执行迁移并构建新镜像，确认没有旧 Flink 作业运行后启动新作业；首次启动的新作业从原始 topic 的最新位置读取，必须确认作业开始消费后再启动 outbox 发布器和采集器。恢复时使用 checkpoint 中的位置。不要让新旧作业同时运行，升级前的业务结果保持不变。

提交器会在 checkpoint 卷留下 `quotes-v2-submitted` 标记，阻止无状态重复提交。TaskManager 故障由 Flink 从 checkpoint 自动恢复；JobManager 故障或作业终止后，先确认旧作业已停止、Kafka 数据仍在，再从同一拓扑的最新完整保留 checkpoint 或 savepoint 恢复，设置 `QUOTE_RESTORE_PATH=file:///opt/flink/checkpoints/...` 重新提交。每个恢复路径只能提交一次；失败时先检查作业状态和 checkpoint，再由运维处理标记，禁止直接无状态重放。拓扑升级需事先准备兼容的 savepoint 或重新制定切换边界。检查作业运行和 checkpoint 成功后移除恢复环境变量，防止下次启动重用旧状态。监控 Flink checkpoint、`quote-outbox` 日志、Kafka 消费延迟和数据库磁盘。

行情页面的分时图展示最近有数据的交易日的一分钟采样均价，采样窗口由 Flink 生成，并非逐笔行情。个股成交量（手）、总市值（元）及市盈率来自腾讯同一时刻的快照，存储在 `realtime_quote_metrics`；接口只在证券和行情时间匹配、且指标采集时间不晚于查询截止时间时返回它们，缺失则为 null。指标保留三天，采集器每天清理一次；市盈率采用上游口径，非正值在页面显示为缺失或亏损。日线、周线和月线通过 `/api/market/history` 按需加载历史；页面不再提供日期或数据截止时间控件。公开行情接口不接受 `as_of` 参数，内部研究仍使用截止时间保证历史可见性。问答可通过 `realtime_quote` 只读工具查询六位代码或带交易所后缀的代码；若六位代码匹配多个交易所，须提供后缀。没有新行情或服务不可用时不会将旧价格作为实时价格回答。

页面历史图表固定使用前复权日线；当天临时日线直接使用同一报价时间的开盘、最高、最低、最新价及累计成交量，周线与月线在此基础上汇总；成交量由上游手数换算为股。临时价格采用当日原始报价作为前复权现价的约定，并非对历史数据执行复权计算；历史数据若未随除权更新，衔接仍可能不一致。当天正式日线入库后会替换临时数据。缺少有效价格、时间不属于当天或行情已过期时不会合成临时 K 线；历史可能缺日时页面提示。

### 当日分时缺口补录

分时数据仅通过独立运维页面 `/ops` 手动补录。可指定当日证券或为全市场启动一批（最多 10 只）。先尝试从 Kafka 恢复原始采样，再查询腾讯当天分时；腾讯数据独立保存，同一分钟优先使用本地采样，行情页面不展示补录标识。任务及请求间隔持久化，腾讯请求间隔至少 30 秒；服务重启后中断未完成任务，不会自动重试或处理旧队列。腾讯返回 429、501 或 WAF 页面时立即停止本批次并暂停到下一个北京时间 09:30；暂停期过后也需要手动发起新任务。停牌、无成交或上游未提供数据的分钟保持缺口。

运维页面沿用项目现有访问方式，没有额外口令；请仅在可信环境提供访问。上线前需升级数据库并重建后端和补录服务；日志可通过 `docker compose logs -f quote-backfill` 查看。

升级到 `0018_quote_capture_only` 前，先停止旧版窗口生产者和消费者，并盘点 `openfinance.realtime_quote_windows` 中 `window_basis <> 'capture_time'` 的数量与时间范围。对原始 Kafka 事件仍可用的范围按现有 `realtime.recompute` 流程重算并核对；重算后仍为旧时间基准的窗口无法还原时直接删除，不备份。确认剩余旧窗口为零后执行 Alembic 升级，再启动新版组件。新版消费旧格式窗口消息时会跳过该消息并提交 offset；迁移会拒绝残留旧窗口，并约束新窗口的时间基准。
